# 正脊行动 · 环境搭建与使用说明

> 一份给接手人看的新手指南：如何把「正脊行动（脊柱健康 App）」的**数据库 → 后端 → 前端**一整套跑起来。
> 本说明只讲"怎么搭、怎么跑"，不涉及对项目代码的任何改动。

---

## 1. 这是什么东西

**正脊行动**是一款面向青少年脊柱侧弯的运动康复辅助 **App（演示项目）**，包含四大功能：脊柱检测、姿态矫正、AI 助教、社区，外加臀桥 / 猫式伸展等训练模块和闯关小游戏。

整个项目分成两半：

| 组成 | 技术 | 目录 | 端口 |
| --- | --- | --- | --- |
| 前端（App） | Flutter（Dart） | `flutter_app_android_source/` | 运行在 Android 模拟器/真机 |
| 后端接口 | Spring Boot 4.0.2（Java 17） | `app-spring/` | **9900** |
| 数据库 | MySQL 8.0 | 库名 `zjxd_app` | **3306** |

> 说明：前端 App 通过 HTTP 访问后端接口取数据，后端连接 MySQL 读写数据。三者都要就位，App 才"活"得起来。

## 4. 第一步：搭建数据库

### 4.1 启动 MySQL

- 确保本机 MySQL 已启动，**默认端口 3306**，账号 `root`，密码 `root`（后端默认按这个连）。

> 如果 MySQL 的 root 密码不是 `root`，需要同步修改后端配置（见第 5.3 节），否则后端连不上库。

### 4.2 导入 SQL

用 Navicat / DBeaver / 命令行都可，按顺序导入 `app-spring/sql/` 下两个文件：

```bash
# 方式一：命令行（需在 mysql bin 目录或已加入 PATH）
mysql -u root -p root < 结构.sql
mysql -u root -p root < zjxd_app数据.sql

# 结构.sql：只建库建表
# zjxd_app数据.sql：包含建表 + 示例数据（登录账号、社区动态、AI 会话等）
```

导入后应出现库 `zjxd_app`，内含 `users`、`community_posts`、`posture_reports`、`motion_records`、`ai_chat_sessions` 等表。

> 两个文件都建议导入：`结构.sql` 保证"干净建表"，`zjxd_app数据.sql` 带上示例数据，App 一打开就有内容可看、有账号可登录。

## 5. 第二步：启动后端（app-spring）

### 5.0 先看后端配置文件

打开 `app-spring/src/main/resources/application.properties`，重点关注这几项（除非必要，**一般不要改**）：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `server.port` | `9900` | 后端监听端口 |
| `spring.datasource.url` | `jdbc:mysql://localhost:3306/zjxd_app...` | 数据库连接串 |
| `spring.datasource.username/password` | `root / root` | 数据库账号密码 |
| `app.video.upload.*` | 远数据库服务器 SFTP 配置 | 训练视频上传转存目标 |

> ⚠️ 若你的 MySQL 密码不是 `root`，把上面的 `password` 改成你的真实密码，再启动后端。

### 5.1 一键启动（推荐，Windows）

双击 `app-spring/startup.bat`，脚本会自动：
1. 检测 Java 环境；
2. 若 `target/` 下没有 jar，则自动用 Maven 构建（首次需联网下载依赖，较慢）；
3. 启动 Spring Boot，监听 `9900`。

看到类似 `Started AppSpringApplication ... on port 9900` 即启动成功。

> 想强制重新构建（改了后端代码后）：在终端运行 `startup.bat rebuild`。

### 5.2 用 Maven 启动（备选）

```bash
cd app-spring
mvnw spring-boot:run       # Windows 用 mvnw.cmd
```

### 5.3 验证后端是否就绪

- 浏览器打开 `http://localhost:9900`（Spring Boot 首页）。
- 或测一个接口，例如登录：
  ```bash
  curl -X POST http://localhost:9900/api/auth/login -H "Content-Type: application/json" -d '{"username":"a","password":"1"}'
  ```
  返回 JSON 即说明「后端 + MySQL」链路通了。

> 常见问题：`startup.bat` 提示"3306 端口未检测到 MySQL"→ 先启动 MySQL；提示连接数据库失败 → 检查 root 密码与 4.1 是否一致。

## 6. 第三步：启动前端（Flutter App）

### 6.1 配置后端地址（★最常见要改的一处）

打开 `flutter_app_android_source/lib/config/app_config.dart`，顶部这一行是后端地址：

```dart
const String kApiBaseUrl = 'http://10.196.101.4:9900';
```

修改规则：
- **模拟器访问本机后端**：`10.0.2.2` 只对官方 AVD 生效，雷电/夜神等不认。稳妥做法是把这里的 IP 改成**你电脑的真实局域网 IP**——在终端执行 `ipconfig`，取 WLAN / 以太网网卡的 IPv4（形如 `192.168.x.x`），不要用 VMware 的 `192.168.x.x`（VMnet 虚拟网卡）。
- 后端必须监听 `0.0.0.0`（`application.properties` 已配置，默认就是这样）。
- 换网络 IP 变了，只需改这一行。

> 例：如果 `ipconfig` 查到本机 IP 是 `192.168.1.100`，就改成 `http://192.168.1.100:9900`。改完后要保证前端 App 所在的设备/模拟器能 ping 通这个地址。

### 6.2 拉取依赖并运行

```bash
cd flutter_app_android_source
flutter pub get            # 首次下载依赖
flutter run -d <设备ID>     # 例如 flutterm run -d emulator-5554，或雷电模拟器的设备名
```

- 打开 `flutter run` 后，按 `R` 可热重启（改 Dart 代码后即时生效，无需重编 APK）。
- 打 Debug / Release 安装包：`flutter build apk --debug` 或 `flutter build apk --release`，产物在 `build/app/outputs/flutter-apk/`。

### 6.3 首次使用

App 打开的登录页**没有内置账号**（示例数据里可能有演示用户），直接用页面上的「注册」功能建一个账号即可登录体验。

## 7. 常用操作速查

| 需求 | 操作 |
| --- | --- |
| 启动数据库 | 启动 MySQL 服务，监听 3306 |
| 后端没起 | 双击 `app-spring/startup.bat`（或 `mvnw spring-boot:run`） |
| 前端连不上后端 | 检查 6.1 的 `kApiBaseUrl` 是否为本机局域网 IP |
| 改了后端代码 | 重新构建：`startup.bat rebuild` 后重启 |
| 改了前端代码 | `flutter run` 中按 `R` 热重启 |
| 打 APK | `flutter build apk --debug / --release` |
| 验证后端 | 浏览器开 `http://localhost:9900`，或调 `/api/auth/login` |

## 8. 常见问题与踩坑

1. **「10.0.2.2 连不上后端」**：仅官方 AVD 支持该别名，雷电/夜神/真机请改用 6.1 的真实局域网 IP。
2. **防火墙挡了后端口**：放行 TCP **9900** 入站，或用 `adb reverse tcp:9900 tcp:9900` 反向代理。
3. **MySQL 连接失败**：确认密码与 `application.properties` 一致；确认 3306 未占用。
4. **首次构建很慢**：Maven / Flutter pub 首次都要联网下载依赖，属正常现象。
5. **App 里有些功能点不开**：这是**演示项目**，大量页面为静态/写死的演示数据（体态报告算法、AI 康复计划均为固定内容），并非"坏掉"，属于刻意设计，遇到可直接跳过。

## 9. 给接手人的重要提醒（务必看）

1. **这是演示项目，静态内容即"契约"**：写死的演示数据、mock 逻辑是**故意的演示设计，不是 bug**，请勿擅自改成"真实实现"。
2. **改动守则**：只改用户明确要求的地方，不顺手"优化"、不重构、不删文件、不重命名，牵一发动全身的改动先与原始作者确认。
3. **安全提醒（仅了解即可，勿向外泄露）**：
   - 用户密码、token 密钥、SFTP 密码均为**明文**硬编码，仅用于本地演示，**严禁直接用于生产部署**；
   - 图床/视频上传指向的是远程服务器（`app.video.upload.*`），本地无该服务器则视频上传功能不可用，属正常。
4. `PROJECT.md` 里有更详细的 API 清单、数据库表结构和技术细节，遇到本说明没讲清的，以它为准。

把整个 `zjxd1` 目录压缩发送（保留目录结构），收件人按**第 4 → 5 → 6 节顺序**操作即可：

4. 改 `app_config.dart` 里后端 IP 为本机局域网 IP，`flutter run` 起前端（第 6 节）；
5. 碰到问题翻第 8、9 节。
